# 15 - Criterios de aceptación del MVP

## MVP terminado cuando se cumpla todo esto

| N° | Criterio | Estado |
|---|---|---|
| 1 | Cliente puede abrir formulario público. | Pendiente |
| 2 | Cliente puede ingresar nombre, teléfono y lugar de trabajo. | Pendiente |
| 3 | Cliente puede seleccionar producto activo. | Pendiente |
| 4 | Cliente puede seleccionar cantidad. | Pendiente |
| 5 | Sistema muestra precio unitario. | Pendiente |
| 6 | Sistema calcula total correctamente. | Pendiente |
| 7 | Pedido se guarda como PENDIENTE y SIN_PAGO. | Pendiente |
| 8 | Admin puede iniciar sesión. | Pendiente |
| 9 | Admin puede ver pedidos pendientes. | Pendiente |
| 10 | Admin puede agendar pedido. | Pendiente |
| 11 | Admin puede cancelar pedido. | Pendiente |
| 12 | Admin puede marcar pedido como pagado. | Pendiente |
| 13 | Pedido pagado pasa a FINALIZADO y PAGADO. | Pendiente |
| 14 | Admin puede marcar pedido como fiado. | Pendiente |
| 15 | Pedido fiado pasa a FINALIZADO y FIADO. | Pendiente |
| 16 | Fiado queda registrado. | Pendiente |
| 17 | Admin puede marcar fiado como pagado. | Pendiente |
| 18 | Productos pueden crearse y editarse. | Pendiente |
| 19 | Productos pueden activarse/desactivarse. | Pendiente |
| 20 | Dashboard muestra resumen básico. | Pendiente |
| 21 | App funciona en celular. | Pendiente |
| 22 | App funciona en PC. | Pendiente |
| 23 | Rutas admin están protegidas. | Pendiente |
| 24 | No hay claves reales en el repositorio. | Pendiente |
| 25 | Existe QA documentado. | Pendiente |

## Condición final

No considerar terminado el MVP si:

- Hay estados inventados.
- Se puede pagar un pedido cancelado.
- Se puede fiar un pedido pendiente.
- El cliente puede manipular precios.
- El panel admin es público.
- El formulario no funciona desde celular.
- No existe documentación mínima.

## Entrega recomendada

Al terminar el MVP, entregar:

```text
README actualizado
.env.example
Carpeta docs
Capturas opcionales
Checklist QA completo
Instrucciones de ejecución
```
